### Fixed-entry identity 边界

- Entry namespace：`entry_id` 只在单个 `AIAPIExecutorConfig` 内唯一；正式 identity 使用 `provider_config_id + selected_entry_id`，并同时绑定 provider/model/reasoning。仅凭同名 entry 不得跨 config/provider 接受。
- Digest 分层：`model_cohort_digest` 锚定 frozen cohort；`model_endpoint_identity_digest` 锚定 cohort member 到 provider endpoint 的语义 identity；`source_provider_config_digest` 锚定批准 safe config；`prepared_execution_config_digest` 只表示 adapter 单-entry/limits 覆盖后的实际运行 config。四者语义不得混用。
- Reasoning：OpenAI 缺失/`None` 为 `default`、空字符串非法、非空字符串规范化比较；GPT member 固定 `high`。SiliconFlow v1 profile 为 `default`，但 `enable_thinking` 单独持久化；JSON-mode 隐式 `false` 可审计，未批准 `true` 不得被 default 标签吞掉。
- Pre-call：formal condition/source config mismatch 在 provider call 前失败；prepared config 只含 approved entry 并固定一次 provider attempt。Experiment 1–4/legacy partial identity 继续兼容。
- Post-call：request/provenance/attempt/raw facts 与 expected identity 对照；response model 缺失/null/空/非字符串写 `missing_resolved_model`，不同或未批准 alias 写 `resolved_model_mismatch`。两者都标记 `model_identity_mismatch`、paper-ineligible，跳过 verifier/checker 并停止后续 unit。source/prepared digests 和 request/provenance/raw/usage refs 同时进入 record。
- Response-fact v2：`PaperModelExecutionRecord.v2` 分开保存 `requested_model`、只来自 provider response 的 nullable `resolved_model` 和 `response_model_status`。成功或 parse-failed submission 都必须审计 raw response；provider failure 无成功 raw output 时使用 `identity_status=not_observed`，继续保留 provider failure 分类且不得伪造 resolved model。旧 v1 raw 外层含义混杂的 `model` 不作为 observed evidence；只允许从历史 `raw_response_json.model` 保守恢复。
- Retry/replacement/resume：复用原 `PaperModelEndpointIdentity` 和批准 source digest；不得从当前 config 仅按 entry 字符串重建。selected entry 503 不会切换 sibling model；config/model/reasoning drift 零调用失败。
- Replay：继续使用 Phase 7 replay guard 只验证历史 artifacts，0 provider calls，不读取 API key env 或当前 config 补写 resolved model；post-call experiment audit 不进入通用 executor。
